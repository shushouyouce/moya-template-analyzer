# 判断流程、证据规则与内部字段

## 一、先拆证据

### 先分清作品与采集载体

用户提供的 MP4 不一定是原作者发布的短视频，也可能是用户为了完整保存一条图文作品而录下的屏幕操作。先识别三层：

1. 原作品：作者实际发布的图文、短视频、口播、直播切片等，这是 `content_form` 的依据。
2. 上下文证据：评论区、搜索联想、账号主页、橱窗和联系方式，用于判断用户信号与承接路径，不并入原作品结构。
3. 采集载体：用户的录屏、截图拼图或下载文件，只描述证据如何被保存，不把“录屏、翻评论、打开主页”误写成作者的内容设计。

只有能确认原作品本身包含评论截图、主页画面或录屏操作时，才把这些写进内容形式和固定结构。

这层区分只用于内部判断。会员发布版不得向读者解释用户如何录屏、截图或采集，也不写“这份素材是……”“原作品不是……”等分析过程；成稿直接从作品第一张图、开头或最值得讲的内容动作切入。

按以下层级记录，不要混写：

1. 作品事实：画面、标题、正文、标签、明确动作、公开数据。
2. 账号事实：主页介绍、其他作品方向、橱窗、团购、联系方式或承接入口。
3. 用户信号：评论里真实出现的提问、表达和行为倾向。
4. 操盘推断：内容机制、目标人群、获客阶段、可能的承接路径。
5. 未知项：制作过程、真实成交、投放情况、数据因果、账号主体意图。

给判断标注“确定、较确定、待确认”。作品数据是历史结果，不自动等于模板复用后的结果。

## 二、六步逆向判断

### 1. 表面主题

这条作品明面上在讲什么。例：孩子长高、发型展示、疤痕恢复、扩列交友。

### 2. 实际动作

它让用户完成什么低成本动作：停留、代入、评论、收藏、搜索、看主页、咨询、购买。主要用途必须写成可观察动作，不写空泛的“帮助获客”。

### 3. 内容机制

判断真正起作用的组合，例如：

- 明确结果＋时间跨度＋过程清单
- 具体愿望＋低门槛口令互动
- 人设反差＋真实服务过程＋结果命名
- 可见结果＋第一人称经历＋搜索词＋主页承接
- 问题状态＋恢复周期＋同部位对比＋克制结论

### 4. 流量价值与业务价值

分开回答：

- 流量价值：为什么会停留、互动、收藏、转发或搜索。
- 业务价值：吸引的人是否接近真实客户，能否进入咨询、到店、购买或交付。

互动高不等于意向高，精准流量也不自动等于成交。没有证据时直接说“只能确认到流量／意向信号，成交待确认”。

### 5. 可复制结构与变量

复制的是机制，不是原文。至少提炼：

- 固定结构：内容推进的顺序。
- 核心情绪或决策机制：愿望、焦虑、好奇、信任、风险比较、结果期待等。
- 可替换变量：人物身份、城市或场景、具体问题、时间、结果、方法、证明材料、承接动作。
- 迁移边界：换到别的行业后，用户心理是否仍成立。

给出2至4个跨赛道例子，每个例子要写成具体题面或结构，不只列行业名。优先选择机制相近的赛道，不为凑数硬迁移。

### 6. 落地与风险

说明使用前提、素材成本、能否持续生产、账号基础、需要的资质、下游承接和最容易失败的地方。

## 三、操盘判断底线

- 流量不等于客户，互动不等于意向。
- 先看用户看完后做什么，再看内容表面说什么。
- 爆过不等于值得入库；要看可复制性、业务相关度和风险。
- 内容和承接是一套系统。没有下游入口时，只能评价内容价值。
- 模板有使用条件，不写“适合所有行业”。
- 迁移时保留用户心理、决策机制或服务结果，不能只换名词。
- 不虚构经历、案例、数据、效果或因果。

## 四、内部记录版

用户要求入库、MCP调用或结构化时，在会员发布版之外输出以下字段；未知值用 `待确认`：

```yaml
template_id:
source_platform:
source_url:
source_date:
track_l1:
track_l2:
threshold: L0|L1|L2|待确认
audience: []
content_form:
stage_primary: S0|S1|S2|S3|S4|S5|S6
stage_secondary:
surface_topic:
actual_function:
traffic_value:
business_value:
landing_path:
transferable_structure:
replaceable_variables: []
migration_examples: []
not_suitable: []
risk_level: A|B|C|D
evidence_facts: []
inferences: []
unknowns: []
aliases_detected: []
confidence: 确定|较确定|待确认
version:
review_status: 待审核|已审核
```

内部记录是供运营、检索和MCP使用的事实层，不用霄策式口语。不要把推断写进 `evidence_facts`。
